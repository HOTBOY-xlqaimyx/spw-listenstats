# PROJECT：SPW 听歌统计插件（spw-listenstats）

> 目标、范围、里程碑、待决策项。**本文件是项目的唯一入口**；代码与使用文档在 `listenstats-plugin/`。

## 一句话

为 Salt Player（SPW）写一个**创意工坊插件**：统计每首曲目的收听时长，按天/按曲目累计，
可选把记录上报到用户自己的服务端；零第三方运行时依赖、行为可远程排障。

## 成功标准

1. 插件能被真实宿主加载并启用（描述符解析 → 加载 → start → 扩展点实例化）—— **已达成的证据见 state.json**
2. 真实播放能被正确统计（会话切分合理、不重复不虚增、拖进度条/倍速不污染）
3. 出问题时，用户发一份 `listenstats.log` 即可定位 —— **0.2.1 起**
4. 零第三方运行时依赖（只用 JDK + SPI API），在宿主的裁剪运行时里不缺类
5. 发版流程固定：改版本号 → 构建 + 自测 → 发布到快速通道并把链接交付

## 范围

**做**：收听统计（本地 JSON）、按天/按曲目聚合、可选 HTTP 上报（含失败重试）、声明式配置页、
远程排障日志、发版与下载通道。

**不做（明确排除）**：播放队列/歌单读写、音频数据流、完整歌词时间轴（API 未开放，issue #19/#20/#24）；
不改宿主、不做任何校验/授权的规避。

   开 = 总时长不丢 + 统计里多一个「未知曲目」条目；关 = 现状。
2. **阶段 2 是否做**（NAS 接收端 + 报告页）。
3. **是否正式上线**（上线才把版本从 `0.x` 升到 `1.0.0`）。
4. **`albumArtist` 34/35 为空**：是文件没标签还是宿主没填 → 计划用日志确认（随下版）。

## 关键约束（决定了很多设计，改动前务必回看）

- 宿主**没有切歌回调**：曲目身份只能靠 `onBeforeLoadLyrics`/`onAfterLoadLyrics` 的 `MediaItem`
- **插件加载时已在播放的那首不会被回调**（宿主只在真正加载歌词时才调），API 也没有「取当前曲目」
- 宿主是 **jlink 裁剪运行时，没有 `java.net.http`**（Windows 与 Linux 实测均如此）
- 模组**默认被禁用**（官方文档：1.6.10 EA 起），必须应用内启用或写插件目录的 `enabled.txt`
- 插件数据目录由宿主的配置路径反推（不硬编码 `%APPDATA%`）
