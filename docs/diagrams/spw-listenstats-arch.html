运行时组件（5 个 + 3 个数据文件）

  • 插件 ListenStats 0.6.1 — SPW 进程内，PF4J 插件
  • 宿主 SPW 1.18.5 — 提供 PF4J 与播放回调（无切歌回调）
  • 接收端 spw-receiver 0.2.1 — 容器，:8199，收数 + 聚合
  • 静态站容器 — nginx，:8123，托管入口页 / 报告页 / 组件图 / 下载
  • 报告页 v0.1.0 — 纯前端，跑在你浏览器/手机里
  • 数据文件：listenstats.json / report-queue.json / report-data.json
  • 本地报告（默认形态）：插件自动刷新「页面 + 内联数据」的单文件 HTML，无需 NAS 即可查看

一次播放怎么走到页面上

  • 宿主回调 → StatsEngine 切会话（单次 ≤3000ms，空闲 60s 结算）
  • 结算 → 入队 + 本地累计（listenstats.json 全量）
  • Reporter POST → :8199 → 追加 jsonl（2xx 才出队）
  • 接收端聚合 → report-data.json 写进静态站目录
  • 浏览器打开 :8123/spw-report/ 同源 fetch 渲染
  • 升级/手动上报即使没有新会话也会推一份纯摘要

两条铁律（踩过的坑）

  • 事件走队列，快照必须能独立送达：把 summary 搭在会话队列上 → 页面永远不更新
  • 数量级不同源：总量/每日来自插件全量累计，会话明细只覆盖开启上报之后
  • 未归因时长（0.7.0+）：宿主没给曲目信息的那段计入总量与每日，但单独成字段、不进榜单
  • 宿主 jlink 运行时无 java.net.http → 只能用 HttpURLConnection
  • fnOS 挂载卷权限会退化成 000 → 写入后必须显式 chmod 644
